## 📌 문서 내용 요약

**OS/DB 계정 신청서 상신/결재 시스템** 전체 설계:

### 1) 핵심 플로우 (P1~P11)
```
신청서 작성 → ①필수항목 검증 → ②중복체크(계정/신청서) → ③제목 특수문자 검증
→ ④파일 검증(20MB/5개/100MB 초과 시 상신 불가) → 상신
→ 결재라인 생성(상신자 → 요청부서 관리자 → 순차 결재자)
→ 결재 단계별 메일 발송(결재요청/결재완료) → 최종결재 → 계정 생성/변경/폐기
```

### 2) 검증/예외 처리
- 필수 작성 항목 누락 → 안내 팝업, 상신 불가
- 계정/신청서 중복 검출 → 중복 판업창 출력
- 시작/종료 일자 검증, 첨부파일 검증 (개수 5개·개별 20MB·총 100MB)
- 모든 테이블 적재 실패 시 **전체 데이터 롤백** + 실패 알림
- 재상신 케이스: 최종결재 코드 "R" 강제 설정

### 3) 데이터 설계 (테이블 + ERD)
| 그룹 | 테이블 |
|:--|:--|
| 신청서 관리 | APL_MASTER_T(신청서 마스터)(통괄) / APL_ASSET_T(신청서 자산) / APL_USER_T(신청서 사용자) / APL_USER_T(신청서 사용자)_OS·DB·APP·WORK / APL_APPR_LINE_T(결재 라인)(결재) |
| 양식 관리 | APL_MANAGER_T(양식 관리자) / COMPUL_OBJ_T(필수구분)(필수구분) / REQ_KIND_T(신청유형)(신청유형) / ITEM_MAPPING_T(항목 매핑) / REFER_T(참조) / APPR_LINE_T(결재선) |
| 자산 관리 | ASSET_MASTER_T(자산 마스터) / _OS_T(운영체제) / _DB_T(데이터베이스) |
| 계정 이력/권한 | ACCOUNT_HIST_T(OS 계정 이력) / _DB_USER_T(DB 계정) / USER_MAPPING_T(사용자 매핑) / SERVICE_COL_MAPPING_T(서비스 컬럼 매핑) / AUTH_DELEGATION_T(권한위임)(권한위임) |

- 적재 순서: 자산 → 신청서 양식 → 신청서 → 계정 생성/변경/수정 → 계정 이력
- 자산번호·문서번호·필수구분 복합 인덱스, 동일 자산번호 검증

### 4) 기술 스택 (문서에서 보이는 것)
- Java Service (비즈니스 로직), [GUI 개발 도구] 화면/트랜잭션
- DB 트랜잭션 Commit/Rollback, 반복문 기반 대량 적재
